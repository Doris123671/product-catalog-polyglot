This assignment was a useful introduction to polyglot persistence, where multiple database systems are used together for different strengths. MongoDB is best for flexible document storage, especially when data such as product catalogs contains arrays and varied attributes. Redis is optimized for fast, in-memory operations, which makes it ideal for caching, leaderboards, and event-driven messaging. PostgreSQL with pgvector is especially strong for semantic search because it can store vectors and perform similarity queries efficiently.

In practice, I would choose MongoDB when I need a flexible schema for catalog or content-heavy data. I would choose Redis when response time and transient state are more important than durability, such as caching API results or maintaining live rankings. I would choose PostgreSQL when I need relational consistency and more advanced analytics or vector similarity search. The most interesting part of the project was seeing how the systems complement one another rather than compete. A catalog can be stored in MongoDB, cached in Redis, and enriched with semantic discovery in PostgreSQL, which demonstrates how modern applications can combine different database models under one architecture.
